# Чтение таймингов/частоты/напряжения памяти на Xeon E5 v3/v4 (X99/C610) — путь-инструкция для ИИ-сессий

> **Цель документа:** любая новая ИИ-сессия (или человек) по этой инструкции
> за 10–15 минут считывает **частоту, tCL/tRCD/tRP/tRAS/tRFC и напряжение**
> на серверных платах, где SPD EEPROM недоступны из ОС, — включая машины,
> где карта регистров ещё НЕ известна (раздел 5 — алгоритм реверса).
>
> **Главный вывод, на который ушли дни:** на Xeon EP тайминги лежат в
> **расширенном конфигурационном пространстве uncore-устройств шины PCI 0xff
> (ECAM, 4 КБ на устройство)**. Никаких MSR, никаких драйверов, никакой
> Windows. Всё читается из Linux. НЕ пытайся идти через SMBus/SPD, MCHBAR
> или CPU-X — эти пути тупиковые (доказательства в разделе «Ловушки»).

## 1. Карта регистров DRAMC (проверенная)

Доступ: любой root-чтение 4K-конфига устройства. В sysfs эти устройства
видны как CF8-нумерация (13.x/16.x) и имеют cfg_size=4096, то есть
**достаточно обычного чтения `/sys/.../config`**:

```python
cfg = open("/sys/bus/pci/devices/0000:ff:13.1/config","rb").read(0x400)
```

### ff:13.0 = 8086:6fa8 «MC0 global» (зеркало MC1: ff:16.0 = 6f68)

| Смещение | Биты | Поле | Пример (1866 CL13) | Достоверность |
|---|---|---|---|---|
| `0x104` | `[4:0]` | **tRAS** (такты) | `0x1f` = 31 | ✓✓✓ |
| `0x104` | `[15:12]` | **tWR** | `0xe` = 14 (= 15 ns) | ✓✓ |
| `0x108` | `[15:12]` | **множитель DRAM** | `0xe` = 14 → 1866.6 MT/s | ✓✓✓ (perf) |
| `0x108` | `[23:16]` | **tFAW** | `0x13` = 19 (= 20 ns) | ✓✓ |
| `0x10C` | `[23:20]` | **tMOD** | `0xc` = 12 (= 12 ns) | ✓✓ |
| `0x11C` | `[23:16]` | **tRFC** | `0xba` = 186 (= 200 ns, 8Gb die) | ✓✓✓ |
| `0x11C` | `[19:16]` | **tCWL** (или tMRD — оба 10) | `0xa` = 10 (CL13→CWL10) | ✓✓ |
| `0x190` | `[31:24]` | **tRRD/tWTR/tRTP** (все 7.5 ns→7) | `0x07` = 7 | ✓✓ |
| `0x1A0` | `[11:8]/[7:4]` | tCCD=4 / tCCD_W=5 (константы DDR3) | `0x445c245e` | ✓ |

### ff:13.1 = 8086:6f71 «MC0 timing» (зеркало MC1: ff:16.1 = 6f79)

| Смещение | Биты | Поле | Пример | Достоверность |
|---|---|---|---|---|
| `0x180` | `[7:0]` / `[15:8]` / `[23:16]` | **tCL / tRCD / tRP**, кодировка: `значение − 6` | `0x070707` → 13-13-13 | ✓✓✓ |
| `0x274` | `[7:0]` | **tREFI ÷ 32** | `0xe4` = 228 → 7296 тактов = 7.82 мкс | ✓✓✓ (228 — уникальная подпись 7.8µs/32) |

tRC = tRAS + tRP (производная, в регистре не хранится).
CR (1N/2N) в регистрах не подтверждён; для 4Rx4 RDIMM @1866 BIOS
ставит 2N. Кандидаты на проверку BIOS-diff: `6f71@0x170` (=1),
`6fa8@0x124` (=2), `6f71@0x318[2:0]` (=7).

Частота: `MT/s = множитель × 133.333` (BCLK на EP фиксирован 133.33 МГц
для стандартных профилей). Напряжение в регистрах MC нет: бери из SPD-базы
по партномеру (DDR3L=1.35, DDR3=1.5, DDR4=1.2) или DMI type 17.

### Thermal Control-блоки: температура каждого DIMM

| sysfs | ID | Канал |
|---|---|---|
| `ff:14.0` | 6fb0 | MC0 Ch0 (A) |
| `ff:14.1` | 6fb1 | MC0 Ch1 (B) |
| `ff:17.0` | 6fd0 | MC1 Ch0 (C) |
| `ff:17.1` | 6fd1 | MC1 Ch1 (D) |

| Смещение | Биты | Поле | Пример | Достоверность |
|---|---|---|---|---|
| `0x150` | `[7:0]` | **температура DIMM0, °C** | 45 покой / 75 стресс | ✓✓✓ (холод/горячий дифф + обратимость + имя в pci.ids) |
| `0x154` | `[7:0]` | **температура DIMM1, °C** | | ✓✓✓ |

`[31:24]=0x0f` константа. Буквы каналов A..D и порядок слотов 1/2 —
допущение (значения — настоящие DTS из кремния). fn4/fn5 (6fb4/6fb5 =
Ch2/Ch3) на этой плате не используются. Метод находки — раздел 4.6.

### Остались нераскодированными (кандидаты для BIOS-diff)

- `6fa8@0x10C = 0x00c841d2` byte0=210/byte2=200 — кандидаты на tXS/tXSR
  (tRFC+10ns≈196, близко к 200/210).
- `6f71@0x24C/0x250/0x25C/0x260 = 0x070007f8` ×4 — перенг-дубликаты
  tCL=13 ([15:8]=7, [31:24]=7) + байт 0xf8=248 (?).
- `6f71@0x27C/0x280 = 0x20004001 / 0x00000181` — tREFI-множитель?
- `6f71@0x2BC+ = 0x0a418820` ×4 (по DIMM) — Vref/ODT per-DIMM?
- CR (1N/2N) — см. примечание в таблице выше.
- Динамические (НЕ трогать как конфиг): `6fa8@0x118`, `@0x120`, `@0x180`, `@0x18C`.

## 3. Ручное чтение (без утилиты, за 30 секунд)

```bash
# tCL/tRCD/tRP:
sudo dd if=/sys/bus/pci/devices/0000:ff:13.1/config bs=1 skip=384 count=4 2>/dev/null | xxd
#   было: 07 07 07 00  →  +6 каждый байт  →  13-13-? (третий байт = tRP)

# tRAS, множитель, tRFC:
sudo dd if=/sys/bus/pci/devices/0000:ff:13.0/config bs=1 skip=260 count=4 ... | xxd  # 0x104 tRAS[4:0]
sudo dd ... skip=264 ...   # 0x108 ratio[15:12]
sudo dd ... skip=284 ...   # 0x11C tRFC[23:16]

# независимая проверка частоты (~2 с):
sudo perf stat -a -e uncore_imc/clockticks/ sleep 2
#   MT/s = ticks_в_секунду / 1e6 / 2.0
```

Скрипт-пример: `tools/smbprobe.py` (SMBus) и `tools/cfgsnap.sh` (снимок
всего 0xff) в репо.

## 4. Что делать, если машина ДРУГАЯ (карта регистров неизвестна)

### 4.1. Разведка за 5 минут

```bash
lspci | head -3; lspci -s 00:00.0; uname -r
# 1) SPD через i801 — скорее всего NACK на 0x50-0x57 (это НОРМАЛЬНО для EP):
sudo i2cdetect -y 0          # модули: modprobe i2c-i801 i2c-dev
# 2) устройства uncore:
ls /sys/bus/pci/devices/ | grep ':ff:'
sudo python3 -c "
import glob
for p in sorted(glob.glob('/sys/bus/pci/devices/0000:ff:*/config')):
    d=open(p,'rb').read(0x400)
    nz=sum(1 for i in range(0x100,len(d),4) if d[i:i+4]!=b'\0\0\0\0')
    print(p.split(':')[1:], '%04x:%04x'%(d[2]|d[3]<<8, d[0]|d[1]<<8), 'nz>0x100:', nz)"
```

### 4.2. Полный ECAM-дам (если sysfs обрезает до 256 байт)

`tools/ecamdump/` — модуль ядра: парсит MCFG (**base по смещению 44 от
начала таблицы!**), ioremap'ит 1 МБ на шину 0xf8-0xff, пишет каждый
непустой девайс в `/tmp/ecam_ff.bin` (16-байтный маркер + 4096 данных).

```bash
cd tools/ecamdump && make && sudo insmod ecamdump.ko && sudo rmmod ecamdump
```

Модуль заодно проверяет MSR 0xF0 (MCHBAR): на EP он читается с #GP —
это нормально, MCHBAR на EP не существует.

### 4.3. Поиск DRAMC в дампе

Признаки «блока настроек» (а не тренировки/статистики):
1. **Идентичность зеркал.** EP имеет 2+ идентичных контроллера (MC0/MC1):
   ищи пары устройств с побайтово одинаковым содержимым (у нас 6fa8↔6f68,
   6f71↔6f79). Тренировочные блоки (DDRIO) между зеркалами РАЗЛИЧАЮТСЯ
   (перенг-маржи), конфиг — нет.
2. **Стабильность во времени.** Сделай два дампа с паузой 30 с — конфиг
   не меняется, счётчики (thermalfan, error counters, 0x118/0x120 у 6fa8)
   меняются.
3. **Значения в тактах.** Ищи байты/поля в диапазоне 5..255, которые
   проходят проверку 4.4.

### 4.4. Раскодировка по трём якорям (обязательна!)

Любую гипотезу проверяй ТРЕМЯ независимыми источниками, иначе это
самообман (у меня на «красивых» догадках умерло несколько регистров):

1. **JEDEC-профиль.** Определи тип памяти и скорость из DMI
   (`dmidecode -t 17`) и партномера. Для DDR3-1866: 13-13-13-31,
   tRFC=200ns(8Gb)/160ns(4Gb); DDR3-1600: 11-11-11-28, tRFC=110ns(4Gb);
   DDR4-2133: 15-15-15-33, tRFC=280ns(8Gb)... Поля вида `0x07` при CL13
   ⇒ кодировка «−6» (Intel классика, встречается и в MCHBAR клиентов).
2. **perf-измерение частоты** (`uncore_imc/clockticks`) — якорь для
   множителя: `ratio × BCLK` обязано совпасть с измерением до ~0.1%.
3. **tRFC в наносекундах:** `поле × tCK ≈ 160/200/280/330/450 ns` для
   известного density — это почти уникальная подпись (у нас 186×1.0715
   = 199.3 ns → 8Gb die, идеально).

### 4.5. Дораскодировка неизвестных полей: BIOS-diff (детерминированный метод)

```bash
sudo tools/cfgsnap.sh _refs/cfgsnap_A     # снимок №1 (текущий BIOS)
# → перезагрузка → BIOS → поменять ОДНУ настройку (напр. DRAM freq
#   1866→1600 или tCL 13→11) → загрузиться →
sudo tools/cfgsnap.sh _refs/cfgsnap_B
python3 tools/cfgdiff.py _refs/cfgsnap_A _refs/cfgsnap_B
```

Изменившиеся поля = регистры этой настройки. Третья точка (ещё одна
настройка) снимает все сомнения. Снимай ТОЛЬКО конфиг-устройства 13.x/16.x
(остальное — шум счётчиков).

### 4.6. Поиск температуры DIMM: холод/горячий ECAM-дифф (без единой записи!)

Контроллер памяти хранит per-DIMM DTS у себя в ECAM (нужен для
температурно-компенсированного refresh), даже когда OS-PECI/TSOD/IPMI
мертвы. Метод:

1. **Дамп A** в покое: `sudo insmod tools/ecamdump/ecamdump.ko` (даст
   `/tmp/ecam_ff.bin`, шины 0xf8-0xff) → сохранить как A;
2. **Разогрев**: `./tools/membw 44 2500 512` (6-13 мин). Следи за
   температурой и останавливай у ~75-80°C — память греть можно,
   перегревать нельзя;
3. **Дамп B** посреди разогрева, **дамп C** после 10-15 мин остывания;
4. Дифф A/B/C: кандидаты — байты 30..90, выросшие на 5-15° под нагрузкой
   и **вернувшиеся** при остывании (якорь обратимости). Отбрасывай
   счётчики (двигаются в обе стороны) и PRNG-блоки (шум вроде
   0x1a0-0x1f0 у 6fb0);
5. Подтверждение: имена блоков в `pci.ids` («… Thermal Control») и
   правдоподобие величин.

Так на X99-T8 нашлись 6fb0/6fb1/6fd0/6fd1 `+0x150[7:0]`/`+0x154[7:0]`
(ловушка 13). Записи в конфиг-пространство не потребовались вообще.

## 5. Ловушки (проверено, наступать не нужно)

| # | Ловушка | Реальность |
|---|---|---|
| 1 | «SPD NACK ⇒ тайминги недоступны» | SPD действительно NACK (вися на SMLink/ME), но тайминги в ECAM 0xff. Не сдавайся. |
| 2 | MCFG base «по смещению 16/52» | Смещение записей MCFG = **44** (после 36-байтного ACPI-заголовка + 8 reserved). У нас base=0x80000000; кривой парсинг дал 0xE0000000 и неделю призрачных нулей. |
| 3 | «sysfs показал нули за 0x100 ⇒ регистров нет» | У части устройств cfg_size=256 и sysfs ОБРЕЗАЕТ чтение. Это не нули, это обруб. Модуль ecamdump решает. |
| 4 | Нумерация CF8 ≠ ECAM | На шине 0xff sysfs (CF8) и ECAM нумеруют устройства со сдвигом +6 (sysfs 13.x = ECAM 19.x). Значения те же — не пугайся, сверяй device ID. |
| 5 | `/dev/mem` mmap/read MMIO | EPERM (iomem strict) даже при lockdown=[none]. Только модуль ядра (lockdown off → unsigned insmod ок). |
| 6 | MSR 0xF0 (MCHBAR) | На EP **не существует** (#GP). Клиентские декодеры (CoreFreq, MCHBAR+0x4000) тут бесполезны. |
| 7 | CPU-X на Linux | Вкладка «Память» = чистый DMI, ничего не читает из MC. |
| 8 | SMBus 0x44 | ACK-ает, но не PMBus и не EEPROM (вероятно Intel SVID VRM). Напряжение бери из SPD/базы. |
| 9 | `echo pass | sudo -S python3 <<EOF` | Heredoc крадёт stdin sudo → «Authentication failed». Пиши скрипт в файл. |
| 10 | «Раскодировка очевидна» | 0x00000019 ≠ tRAS (динамический счётчик!), «186» в 0x118 был ложным — настоящий tRFC в 0x11C. Всегда: зеркала + время + JEDEC. |
| 11 | HWiNFO/CPU-Z реверс | HWiNFO распаковывается `upx -d` (26 МБ кода), но путь к значениям — IOCTL-абстракция + gettable-таблицы, статический трассировочный путь дорог. Референс «как они это делают» полезен, но эмпирика быстрее. |
| 12 | perf без root / в контейнере | Нужен root; парсинг вывода — с учётом `\u202f` (узкий пробел) в числах. |
| 13 | «HWiNFO показывает t° DIMM, а в Linux OS-PECI нет ⇒ недоступно» | PECI действительно закрыт (x86-моста в ядре нет, BMC нет, TSOD за ME, SuperIO «Agent0 Dimm0» мёртв). НО per-DIMM t° лежит в ECAM: Thermal Control-блоки MC **6fb0/6fb1 (sysfs ff:14.0/14.1) и 6fd0/6fd1 (ff:17.0/17.1), +0x150[7:0] и +0x154[7:0] = °C DIMM0/DIMM1 канала** (MC0=каналы A/B, MC1=C/D). Открыто холод/горячим диффом ECAM (см. 4.6): idle 43-49°C, стресс membw 75°C, при остывании значения вернулись. Чтение — sysfs config >64B (только root). Никаких записей в конфиг делать не нужно! |

## 7. Чеклист «я всё проверил, можно докладывать пользователю»

- [ ] Значения с зеркал MC0/MC1 совпадают побайтово
- [ ] Множитель × BCLK = perf-измерение (±0.1%)
- [ ] tRFC×tCK попадает в JEDEC ns для известного density
- [ ] tCL-tRCD-tRP-tRAS = валидному JEDEC-профилю скорости из DMI
- [ ] Два дампа с паузой: конфиг-поля не дрейфуют
- [ ] ECC: CE/UE за сутки (или с загрузки) — назвать числом; UE>0 = алерт
- [ ] AER PCIe в журнале — это НЕ память (шина NVMe/GPU), не пугать пользователя
- [ ] (если менялся BIOS) cfgdiff подтвердил привязку поля к настройке

## 8. Дорожная карта (что ещё не взято)

Раскодировано и проверено: tCL, tRCD, tRP, tRAS, tRC (дерив.), tRFC, tWR,
tFAW, tCWL, tRRD/tWTR/tRTP (общая группа 7.5ns), tMOD, tREFI, множитель,
частота, **температура каждого DIMM** (Thermal Control, 4.6). Не
подтверждено регистрами: CR (для 4R RDIMM=2N), tXS/tXSR,
Vref/ODT. Финализация спорных полей (tCWL vs tMRD, разделение
