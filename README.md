# ramspd — чтение SPD EEPROM модулей RAM напрямую через SMBus

Утилита на чистом Python (без зависимостей) читает EEPROM на каждой планке
памяти и показывает то, что модуль «говорит» о себе: **частоту, полные
тайминги (ns и в тактах), напряжения, XMP-профили**, производителя,
партномер, объём. Это те же данные, из которых BIOS строит
`DRAM Timing Table`; CPU-Z на Windows показывает их же (он тоже читает SPD,
на Windows — через свой драйвер).

## Быстрый старт

```sh
# 1. Однократно настроить доступ (от root):
su -c './setup_permissions.sh $(logname)'   # из папки репозитория
#    затем перезайдите в сессию (или перезагрузитесь)

# 2. Запуск:
python3 ramspd.py              # все DIMM (SPD через SMBus)
python3 ramspd.py --live       # live-режим: DMI + измерение частоты счётчиками IMC
python3 ramspd.py --bw         # + тест пропускной способности DRAM (STREAM)
python3 ramspd.py --json       # машинночитаемый вывод
python3 ramspd.py --bus 0 --hex
python3 ramspd.py --dump-dir dumps   # сохранить сырые SPD в .bin
python3 ramspd.py --from-file dumps/dimm-0-0x50.bin  # декодировать файл
```

Без настройки доступа можно запускать разово от root:
`su -c 'python3 ramspd.py'`.

## Live-режим (серверные платы: Huananzhi X99 и т.п.)

На серверных и «серверных по дизайну» платах (Xeon E5 v3/v4, чипсет C610)
SPD EEPROM физически подключены к SMLink/ME, а не к обычному SMBus, и из ОС
не видны — их не читает ни один Linux-инструмент (ни i2c-tools, ни CPU-Z
через свой драйвер SMBus). BIOS читает SPD в SMM и пишет результат в SMBIOS.

На таких платах утилита автоматически переключается в live-режим
(или явно: `--live`, нужен root из-за dmidecode/perf):

- **фактическая частота памяти** измеряется напрямую счётчиками
  производительности контроллера (`perf uncore_imc/clockticks`) —
  проверено: 1866.7 MT/s на E5-2696 v4;
- **живые тайминги DRAMC** читаются из расширенного конфигурационного
  пространства uncore-устройств (шина PCI 0xff, ECAM 4 КБ). Карта
  регистров выведена эмпирически (зеркала MC0/MC1 идентичны, значения
  совпадают с профилем JEDEC и независимым измерением частоты):

  | Регистр | Поле | Показатель |
  |---|---|---|
  | `ff:13.1` (8086:6f71) `+0x180` | [7:0], [15:8], [23:16] (код −6) | tCL, tRCD, tRP |
  | `ff:13.1` (8086:6f71) `+0x274` | [7:0] ×32 | tREFI (7296 = 7.82 мкс) |
  | `ff:13.0` (8086:6fa8) `+0x104` | [4:0] / [15:12] | tRAS / tWR |
  | `ff:13.0` (8086:6fa8) `+0x108` | [15:12] / [23:16] | множитель ×BCLK / tFAW |
  | `ff:13.0` (8086:6fa8) `+0x10C` | [23:20] | tMOD |
  | `ff:13.0` (8086:6fa8) `+0x11C` | [23:16] / [19:16] | tRFC / tCWL |
  | `ff:13.0` (8086:6fa8) `+0x190` | [31:24] | tRRD/tWTR/tRTP (7.5 ns) |

  Зеркало второго контроллера: `ff:16.0`/`ff:16.1` (6f68/6f79).
  Чтение требует root (extended config space). Проверено на
  Huananzhi X99-T8 / E5-2696 v4 / 8×DDR3L-1866: **13-13-13-31, tRFC 186,
  tWR 14, tFAW 19, tCWL 10, tRRD/tWTR/tRTP 7, tMOD 12, tREFI 7296,
  14×133.33 = 1866.7 MT/s**;
- объём/тип/ранги/производитель/партномер — из SMBIOS;
- **статистика ECC-ошибок DRAM** — из счётчиков EDAC
  (`/sys/devices/system/edac/mc*`): исправленные (CE) и неисправимые (UE).
  Счётчики накопительные (сброс на перезагрузке), поэтому утилита копит
  снапшоты в `~/.cache/ramspd/ecc_state.json` и показывает дельту за
  последние ~24 ч; пока базы нет — итоги с загрузки. Отдельной строкой —
  события ядра за сутки из `journalctl`: MCE и PCIe AER (это ошибки
  шины NVMe/GPU, а не памяти — не путать);
- тип модуля и **напряжение** — из базы по партномерам (DMI таких плат
  обычно отдаёт Unknown);
- **температура модулей** — из Thermal Control-регистров контроллера
  памяти Xeon EP (шина PCI 0xff: 6fb0/6fb1/6fd0/6fd1, +0x150/+0x154[7:0],
  °C на DIMM) — работает даже когда память спрятана за ME. Резервные
  пути для других плат: peci-dimmtemp hwmon, SuperIO-метки Dimm,
  i2c TSOD, IPMI/BMC. Найдено холод/горячим ECAM-диффом: idle 43–49°C →
  стресс membw 75°C → обратимость при остывании;
- не подтверждено регистрами: CR (для 4R RDIMM @1866 = 2N по JEDEC),
  tXS/tXSR, Vref/ODT. Полная карта регистров и методика реверса —
  [docs/AGENT-HOWTO-READ-TIMINGS.md](docs/AGENT-HOWTO-READ-TIMINGS.md).

Для глубокого анализа в `tools/ecamdump/` лежит модуль ядра, выгружающий
полные 4 КБ ECAM всех устройств шины 0xff (пригодся при реверсе; обычная
работа утилиты его не требует).

### Тест пропускной способности (`--bw`)

`python3 ramspd.py --bw` собирает `tools/membw.c` (потоки + AVX2
streaming-сторы, как в эталонном STREAM, плюс ядро чистой записи Write),
гоняет шесть ядер на 3×512 MiB массивах `double` и сравнивает с
теоретическим пиком каналов (MT/s × 8 Б × каналы, каналы из локаторов DMI):

```
--- Пропускная способность DRAM (22 потока, 512 MiB/массив) ---
  Read:      51.9 GB/s (87% пика)     — только чтение, лучший случай
  Write:     49.6 GB/s (83% пика)     — чистая запись (NT-сторы, без RFO)
  Copy:      35.0 GB/s (59% пика)     — 50/50 R/W, упор в turnaround шины
  Scale:     35.7 GB/s (60% пика)
  Add:       47.5 GB/s (80% пика)
  Triad:     47.7 GB/s (80% пика)     — классический показатель STREAM
  Теор. пик: 59.7 GB/s (4 канала × 8 Б × 1866.7 MT/s)
```

Нормы для 4-канальной DDR3-1866: Triad 75–85% пика, Write обычно чуть
ниже Read. Просадка Write при нормальном Read — признак проблем по
траектории записи (канал,termination). Меньше общего — подозрение на
деградацию канала/тайминги. Потоки по умолчанию = физические ядра
(`--bw-threads N` для переопределения); тест грузит память несколько
секунд. Для сравнения: `mbw`, `sysbench memory` дают те же порядки,
но без привязки к теоретическому пику конфигурации.

На обычных десктопных платах (SPD на i801/PIIX4 SMBus) работает полный
SPD-декодер: все тайминги, CAS-таблицы, XMP, CRC.

## Что показывает

| Блок | Источник в SPD (DDR3) |
|---|---|
| Макс. частота (MT/s, PC3-xxxx) | tCK min, байты 12+34 |
| Тайминги на стандартных скоростях (CL-tRCD-tRP-tRAS) | tAA/tRCD/tRP/tRAS + CAS-маска (байты 14–22, 35–38) |
| tCK, tAA, tRCD, tRP, tRAS, tRC, tRFC, tRRD, tWTR, tRTP, tFAW (ns) | байты 12–29, 34–38 |
| Напряжения 1.5/1.35/1.28 V | байт 6 |
| Intel XMP (частота, тайминги, напряжение профиля) | байты 176–254, magic `0C 4A` |
| Объём, ранги, ширина, банки | байты 4–8 |
| Производитель/партномер/серийник/дата | байты 117–149 (JEP106) |
| CRC целостности SPD | байты 126–127 |

DDR4: то же (частота, тайминги, CAS, объём, 1.2 V, производитель) — чтение
двухстраничного EEPROM EE1004 через page-select на 0x36/0x37 (схема ядрового
драйвера `ee1004`). DDR5: распознаётся и дампится в hex (полный декодер —
будущая работа).

## Как это работает

1. SMBus-контроллер чипсета (Intel I801 / AMD PIIX4) виден как `/dev/i2c-N`
   после загрузки модулей `i2c-dev` + `i2c_i801`.
2. SPD EEPROM каждой планки занимает адрес `0x50+i` на этой шине.
3. `rspd/transport.py` делает SMBus-запросы напрямую `ioctl`-вызовами
   (`I2C_SMBUS`, `I2C_RDWR`) — никаких python-smbus/i2c-tools не нужно.
4. Декодеры `rspd/ddr3.py` / `rspd/ddr4.py` разбирают SPD по JEDEC
   (JESD400-5 / JESD400-1). XMP DDR3 — по Intel XMP Spec 1.1.

## Корректность

Формулы портированы 1:1 из i2c-tools `decode-dimms` (GPL-2.0+) и
сверяются тестами:

- `tests/crosscheck_oracle.py` — 31 поле против вывода `decode-dimms 4.4`
  на реальном дампе DDR3 (Crucial Ballistix 8GB 1333/CL9 + XMP 1866):
  **31/31 совпадений**.
- `tests/test_synthetic.py` — синтетические SPD DDR3L+XMP и DDR4 с CRC,
  round-trip по заведомым значениям.
- `tests/test_ecc.py` — логика ECC: дельта накопительных счётчиков по
  снапшот-кэшу (окно, свежая база, перезагрузка) и разбор журнала
  MCE/EDAC/AER. **10/10**.
- `tests/test_dimmtemp.py` — классификация DIMM-температур на фиктивной
  hwmon-иерархии (PECI/SuperIO/TSOD, фильтр мёртвых сенсоров, CPU
  package) и EP Thermal Control-регистры на фиктивном sysfs. **7/7**.

## Структура

```
ramspd.py            CLI-точка входа
rspd/transport.py    SMBus/I2C ioctl (Read Byte Data, Send Byte, RDWR)
rspd/spd.py          скан шин, обнаружение DIMM, чтение (DDR3/DDR4/DDR5)
rspd/ddr3.py         декодер SPD DDR3 + XMP
rspd/ddr4.py         декодер SPD DDR4
rspd/xmp3.py         Intel XMP DDR3
rspd/jep106.py       таблица производителей JEP106 (из decode-dimms)
rspd/dmi.py          SMBIOS/DMI + база напряжений по партномерам
rspd/memclock.py     измерение частоты памяти счётчиками uncore IMC
rspd/epmc.py         живые тайминги из регистров DRAMC (шина PCI 0xff)
rspd/ecc.py          ECC-статистика: счётчики EDAC + журнал за сутки
rspd/dimmtemp.py     температура модулей: TSOD / PECI DTS / IPMI / SuperIO
rspd/membw.py        пропускная способность DRAM (обёртка над membw.c)
rspd/report.py       текстовый/JSON вывод
tools/membw.c        STREAM-подобный бенчмарк (Read/Write/Copy/Scale/Add/Triad)
setup_permissions.sh однократная настройка прав (root)
tests/               тесты (оракул decode-dimms + синтетика + ECC + dimmtemp)
_refs/               референсные материалы (дампы, эталонные декодеры)
```

## Безопасность

Инструмент только читает EEPROM. Единственная запись на шину — служебная
команда выбора страницы DDR4 (адрес `0x36/0x37`, по спецификации SPD5118
содержимое памяти не изменяет; так же делает ядро в драйвере `ee1004`).
Опасности для данных/системы нет; чтение доступно и на включённой машине.

GPL-2.0+ (производная работа: формулы и таблица JEP106 портированы из
